두 방식 비교

1:1 NAT vs. PAT

1:1 NAT Static

내부 IP ↔ 공인 IP를 1:1 매핑. 포트 변환 없음.

장점
  • 포트 소진 없음 — 동시 연결 多 무관
  • 인바운드 가능 — Hybrid Exchange 등
  • 추적·감사 단순 (1 IP = 1 단말)
  • 세션 한계 예측 용이
단점
  • 공인 IP 대량 필요 — 대규모엔 비현실적
  • 비용·할당 부담 (IPv4 고갈)
  • 인바운드 핀홀 → 보안 표면 증가
  • IP 낭비, 풀 효율화 없음

PAT (Overload) NAT44

다수 내부 IP를 소수 공인 IP + 포트로 변환.

장점
  • IP 효율 극대 — 1개로 수천 세션
  • 아웃바운드 보안 기본(인바운드 차단)
  • 대규모 M365에 현실적
단점
  • 포트 소진 — IP당 ~64k, 빠르게 고갈
  • 세션 테이블 부하(CPU·메모리)
  • 로그 상관분석 복잡(IP+포트+시각)
  • 단일 IP 평판 오염 시 광범위 영향
  • 타임아웃 튜닝 필수

권장 아키텍처

혼합 설계 5단계

상위 원칙 먼저 — Optimize/Allow는 로컬 egress + 인스펙션·프록시 우회 + 직접 인터넷. NAT만 거치게.
기본은 PAT 풀 — 사이징표대로 공인 IP 다수 풀로 포트 소진 분산.
1:1 NAT은 예외만 — Hybrid 인바운드, 송신 IP 고정 소수 시스템.
타임아웃 튜닝 — long-lived/UDP에 맞춰 세션 타임아웃·테이블 상향.
분기별 풀 검증 — 활성 사용자·동시연결 증가 추적, 포트 사용률 70% 알람.
운영

모니터링 체크리스트

  • PAT 포트 사용률(IP별): 70% 경고 / 85% 임계
  • 세션 테이블 사용률·생성률 모니터링
  • UDP/QUIC 플로우 타임아웃 적정성
  • 송신 IP 평판(블랙리스트) 점검
  • 분기별 사용자 증가 대비 풀 재산정
실전 적용

글로벌 기업의 실제 적용 사례

NAT 방식 자체를 공개하는 기업은 드물지만, Microsoft가 문서화한 대규모 고객 패턴과 업계 표준 배포를 보면 답은 명확합니다 — NAT 변환량 자체를 줄이고 트래픽을 로컬에서 직접 내보내는 방향입니다.

1

COVID-19 대규모 재택 — Forced VPN → Split Tunnel

가장 광범위한 사례

다수 고객이 내부 트래픽 80% → 외부 클라우드 20% 이하로 역전. 전 트래픽을 VPN으로 강제 백홀하던 기업은 재택 폭증으로 VPN·중앙 egress·NAT 장비가 동시 포화되었다.

Teams·SharePoint·Exchange의 Optimize 엔드포인트(약 20개 IP 서브넷 = 트래픽 70~80%)를 VPN에서 분리해 로컬 직접 송출 중앙 PAT 통과 세션 급감 → 포트 소진·세션 테이블 부하 즉시 완화 (구현 수 시간) 인라인 검사 대신 Tenant Restrictions·Conditional Access(MFA)·Purview DLP로 보안 대체
2

글로벌 분산 지사 — SD-WAN 로컬 브레이크아웃

제조·리테일·물류

본사 한 곳으로 모아 NAT/검사하던 구조에서 본사 중앙 PAT가 병목이 되자, 각 지사에서 직접 인터넷 브레이크아웃으로 전환.

중앙 IP 풀 집중 부하를 지사별 소규모 PAT 풀로 분산 → 포트 소진·단일 IP 평판 오염 영향 축소 Microsoft 권고: 중앙 egress 1곳이면 지역(regional) egress 포인트 추가를 최적화 1순위로
3

규제 산업(금융·공공) — ExpressRoute는 "예외 승인"

특수 요건

엄격한 인바운드·감사 요건 일부 기관이 사설 경로를 검토하나, Microsoft는 ExpressRoute for M365를 권장하지 않으며 사례별 승인이 필요한 드문 예외로 규정.

"고정 전용 경로 + 1:1 NAT 성향"은 기본이 아니라 특수 요건일 때만 — 대부분은 인터넷 + split tunnel
4

중국(PRC) 사용자 — 의도적 백홀 + MPLS egress

지정학적 예외

국경 간 혼잡으로 직접 egress가 불안정. 대부분 기업이 트래픽을 사내망에 모은 뒤 인가된 MPLS로 역외 최적 경로 egress.

egress 지점에 소수 고정 공인 IP가 모여 1:1/소수 PAT 성향 — "로컬 egress 원칙"의 예외
5

벤더별 표준 배포 — 업계가 실제 쓰는 도구

검증된 구현체

Microsoft가 공식 연계 가이드를 제공할 만큼 광범위하게 쓰이는 조합 — 수많은 글로벌 기업이 이 스택으로 운영 중.

VPN split tunnel: Cisco AnyConnect · Palo Alto GlobalProtect · F5 BIG-IP APM · Citrix Gateway · Check Point 클라우드 SWG: Zscaler / Prisma에서도 Optimize 트래픽은 직접 송출 권고 자동화: Endpoints 웹 서비스로 IP/URL 목록 자동 동기화 → 방화벽·PAC 갱신
핵심 교훈: 실제 답은 "1:1이냐 PAT냐"의 이분법이 아니라 — ① 트래픽 식별 → ② 로컬/지역 egress로 NAT 통과량 자체를 축소 → ③ 남는 트래픽만 PAT 풀로 분산하는 단계적 최적화. 1:1 NAT은 인바운드·규제·중국 같은 명시적 예외에서만 등장한다.
