OSPF Cost가 MED로 반영되어 발생하는
Suboptimal Egress

Multi-Site 단일 stretched VRF에서 동일 외부 prefix를 양 site L3Out으로 받을 때, OSPF cost가 MP-BGP MED로 상속되고 site간 EVPN으로 보존되어, 양 site 모두 cost 낮은 한쪽 L3Out으로만 나가는 현상. 실측 데이터로 메커니즘을 규명하고 Local Preference로 해결한다.

OSPF Cost → BGP MED 상속 MED 4 EVPN 보존 (transitive) Suboptimal Egress / Tromboning Fix · Set Local Preference 200
근본 원인
MED = OSPF cost + BL cost
결정 속성
BGP MED (낮은 쪽 승)
잘못된 해법
OSPF Cost 조정 (취약)
올바른 해법
Local Preference 200
!
이 문서의 핵심 반전

일반적으로 "ACI는 OSPF cost를 MED로 반영하지 않는다"고 알려져 있으나, 실측 데이터는 그 반대를 보여준다. 이 환경에서는 OSPF cost가 MED로 상속되고 site간 EVPN으로 보존되어 best-path를 결정한다. 따라서 OSPF cost 조정이 아니라 Local Preference가 정답이다. (상세 정정: §9)

01 증상 & 실측 데이터

1.1 증상

Multi-Site로 연결된 두 site(Site1, Site2)가 단일 stretched VRF를 공유하고, 동일한 외부 네트워크 A를 각 site의 local L3Out에서 OSPF로 수신한다. 그런데 양 site의 endpoint가 모두 Site1-L3Out으로만 외부로 나가, Site2의 트래픽이 ISN을 건너 Site1으로 우회(tromboning)하는 suboptimal egress가 발생한다.

1.2 실측 데이터

경로 ① Core OSPF Cost ② Border Leaf 가산 Cost ③ MP-BGP MED (①+②)
Site1-L3Out / A 48 +11 59 ← 더 낮음
Site2-L3Out / A 58 +4 62
관측 지점Site1-L3Out MEDSite2-L3Out MEDRIB 설치 경로 (best)
Site1 ACI Leaf5962Site1-L3Out
Site2 ACI Leaf5962Site1-L3Out ⚠️
◎
데이터에서 읽히는 3가지 사실

① OSPF cost 순서(48 < 58)가 MED 순서(59 < 62)로 그대로 보존 → OSPF cost가 MED에 반영됨.

② 양 site leaf가 동일한 MED(59/62)를 봄 → MED가 site간 EVPN을 건너 보존됨.

③ 양 site 모두 MED 낮은 Site1-L3Out(59)을 선택 → MED가 실제 결정자이며, Site2는 suboptimal.

02 OSPF Cost → BGP MED 매핑

ACI Border Leaf가 OSPF external route를 fabric MP-BGP(VPNv4)로 redistribute(interleak)할 때, OSPF total cost가 BGP MED로 상속된다. MED 값은 다음 공식으로 형성된다.

MED  =  Core가 광고한 OSPF Cost  +  Border Leaf ↔ Core 링크 OSPF Cost
Site1 : 48 + 11 = 59   |   Site2 : 58 + 4 = 62

2.1 offset(+11 / +4)이 다른 이유

가산되는 cost는 각 site의 Border Leaf가 외부 Core까지 도달하는 자신의 OSPF interface/SPF cost다. 두 site의 Border Leaf↔Core 링크 OSPF interface cost(대역폭 기반 또는 수동 설정)가 다르기 때문에 offset이 11 vs 4로 달라진다.

i
문서화 수준에 대한 정직한 고지

이 "OSPF cost → MED 상속" 동작은 Cisco 공식 문서에 명시적으로 기술되어 있지는 않다(ciscodata 확인). 그러나 ACI 전용 모델(ciscoDeepNetwork) 분석과 현장 실측이 정확히 일치하므로 실제 동작은 확정적이다. 일반 NX-OS의 redistribute ospf가 OSPF metric을 MED로 복사하는 것과 동일한 맥락이다.

≠
앞선 일반론과의 차이

"ACI는 IGP 변동이 BGP를 흔들지 않도록 MED를 0으로 둔다"는 일반론이 흔히 인용되지만, 이 환경의 실측은 MED가 OSPF cost를 반영함을 보여준다. 환경/릴리스/구성에 따라 동작이 다를 수 있으므로 반드시 실제 장비에서 MED 값을 확인해야 한다.

03 MED는 Site간 EVPN으로 보존된다

이 현상의 두 번째 핵심. Local Preference와 MED는 site 경계에서의 거동이 정반대다.

속성Site간 eBGP/EVPN 경계 거동이 시나리오에서의 의미
MED (Metric) 보존(carried) — VPNv4/EVPN 속성으로 end-to-end 전달 Site2 leaf도 Site1 경로의 MED 59를 그대로 봄 → 양쪽 동일 판단
Local Preference 제거(stripped) — non-transitive, eBGP 경계에서 삭제 한 site에서 설정해도 다른 site로 안 넘어감 → 해결책의 열쇠
Site2 Border Leaf — OSPF→MP-BGP
A에 MED 62 부여 (58+4)
↓iBGP VPNv4 (site 내부)
Site2 Spine
MED 62 유지
↓eBGP EVPN over ISN — MED 보존, LocPref 제거
Site1 Spine

↓
Site1 Compute Leaf
Site1경로 MED 59 vs Site2경로 MED 62 → 59 승
✓
왜 이게 해결의 단서인가

MED는 보존되어 끄기 어렵지만, Local Preference는 site 경계에서 자동 제거되므로 각 site에서 독립적으로 설정해도 서로 간섭하지 않는다. 그래서 "각 site가 자기 local L3Out 선호"를 대칭적으로 구현할 수 있다. (→ §6)

04 왜 Suboptimal이 발생하나 — Vantage Point

경로 선택 결과는 "어느 leaf에서 보느냐"에 따라 다르다. 이 구분이 결정적이다.

4.1 Border Leaf 관점 — local이 자동으로 이김

경로성격Next Hopbest-path 판정
자기 site L3Outlocally originated0.0.0.0✓ 승 (Locally Originated 규칙)
remote site L3OutiBGP/EVPN 수신remote TEP패

Border Leaf에서는 자기 L3Out 경로가 locally originated라, best-path 상위 규칙에서 이긴다. MED까지 가지 않음.

4.2 Compute Leaf 관점 — 여기서 문제 발생 ⚠️

경로성격 (compute leaf 입장)Locally Originated?
Site1 L3Out 경로iBGP 수신 (자기 site SBL로부터)아니오
Site2 L3Out 경로iBGP 수신 (SBL=ISN gateway로부터)아니오
⚠
endpoint는 compute leaf에 있다

Compute Leaf 입장에서는 두 경로 모두 iBGP 수신이라 "Locally Originated" tie-break이 건너뛰어진다. 그래서 best-path가 아래로 흘러 내려가 MED(59 vs 62)에서 결판나고, MED 낮은 Site1(59)이 양쪽 모두에서 승리한다. → Site2 endpoint의 suboptimal egress 확정.

i
"기본 local-site 우선"은?

공식 문서는 "route-map 없으면 IS-IS metric상 가까운 local border leaf 선호"라고 기술하지만, 그것은 MED/LocPref가 동률일 때의 tie-break다. 지금처럼 MED가 다르면 MED가 먼저 결정하므로 기본 local 선호가 깨진다.

05 BGP Best-Path 결정 흐름

Compute Leaf에서 두 경로(Site1 vs Site2)가 비교되는 순서. 현재 결정 지점과 해결 후 결정 지점을 표시했다.

  1. Weight둘 다 0 — tie
  2. Local Preference현재 둘 다 100(tie) → 여기에 200 설정 시 즉시 결판FIX 지점
  3. Locally Originatedcompute leaf에선 둘 다 iBGP → 해당 없음 (skip)
  4. AS-Path 길이동일 — tie
  5. Origin Type동일(보통 incomplete) — tie
  6. MED59(Site1) vs 62(Site2) → 낮은 59 승 = 현재 문제의 원인현재 결정
  7. eBGP > iBGP여기까지 오지 않음
  8. IGP metric to next-hopMED가 같았다면 여기서 가까운 BL 선택
★
전략의 핵심

Local Preference(2단계)는 MED(6단계)보다 훨씬 먼저 평가된다. local 경로에 LocPref 200을 주면, MED 59 vs 62 차이를 비교하기도 전에 결판나서 각 site가 자기 local L3Out을 선택한다.

06 해결책 — Local Preference (대칭 적용)

각 site의 local L3Out import 경로에 Local Preference 200을 부여한다. MED 차이를 덮어쓰고, LocPref는 site 경계에서 제거되므로 양 site가 독립적으로 자기 local을 선호한다.

Site2 Compute Leaf 관점 (해결 후)

속성Site2-L3Out (local)Site1-L3Out (remote)결과
Weight00tie
Local Preference200 (설정)100 (기본)✓ Site2 local 승
MED6259무시됨 (LocPref가 이미 결정)
✕
OSPF Cost 조정은 왜 나쁜가

OSPF cost를 만져 MED를 뒤집으면 일시적으로 고쳐지지만, 외부 토폴로지 변동·링크 장애 시 MED가 다시 흔들려 트래픽이 의도치 않게 넘어간다. 비결정적이고 취약하다. Local Preference는 외부 metric 변동과 무관하게 결정적이다.

✓
두 가지 작동 원리

1. LocPref(2단계)는 MED(6단계)보다 먼저 평가 → MED 59/62 차이를 덮어씀.
2. LocPref는 site간 eBGP에서 strip → Site1의 200은 Site1에만, Site2의 200은 Site2에만 유효 → 대칭적 local 선호 완성.

07 설정 절차 (NDO/MSO 또는 각 Site APIC)

양 site에 대칭으로 동일하게 적용한다. (Site1은 Site1 L3Out에, Site2는 Site2 L3Out에)

  1. Match Rule 생성 — 외부 네트워크 A 매칭
    Tenant > Policies > Protocol > Match Rules for Route Map
    • Match Prefix = 네트워크 A (또는 대상 external subnet / 0.0.0.0/0)
  2. Set Rule 생성 — Local Preference 200
    Tenant > Policies > Protocol > Set Rules for Route Map
    • Set Preference = 200 (기본 100보다 높게)
  3. L3Out Route Map 생성 + Import 방향 적용
    Tenant > Networking > L3Outs > [local L3Out] > Route map for import and export route control
    • Type = Route Control
    • Context = Permit, Match Rule + Set Rule 연결
    • Direction = Import (외부→내부 수신 경로 제어)
  4. External EPG Subnet에 적용
    L3Out > External EPGs > [ExtEPG] > Subnet
    • 해당 subnet에 Import Route Control 활성화 + Route Map 연결
  5. 반대 site에도 동일 적용 (대칭)
    Site2 local L3Out → 동일하게 Set Preference 200
    • 이로써 Site1↔Site1, Site2↔Site2 각자 local 선호 완성
✎
개념 표현 (이해용 — 실제는 GUI/MO)
pseudo · per-site local L3Out import
! 각 site의 local L3Out import에 적용 (대칭)
ip prefix-list NET_A permit A.A.A.0/24
route-map LOCAL_L3OUT_IMPORT permit 10
  match ip address prefix-list NET_A
  set local-preference 200   ! ← 자기 site local 경로 선호 (MED 무시)

08 진단 명령어

ACI leaf의 vsh_lc 셸에서 실행. compute leaf(endpoint 있는 곳)와 border leaf 양쪽에서 비교하는 것이 핵심이다.

leaf · vsh_lc
# 1) line-card 셸 진입 (일반 ACI CLI 아님)
leaf# vsh_lc

# 2) 특정 prefix의 모든 BGP 후보 경로 + 속성 확인 (핵심)
module-1# show bgp vpnv4 unicast vrf <tenant:vrf> A.A.A.0/24

# 3) RIB에 실제 설치된 best 경로만 확인
module-1# show ip route vrf <tenant:vrf> A.A.A.0/24

출력에서 확인할 핵심 컬럼

컬럼의미 / 확인 포인트
NetworkRD:prefix 형식 (VPNv4)
Next Hop0.0.0.0=local 발생 / TEP IP=remote(다른 BL 또는 site)
Metric (MED)여기가 59 vs 62 — 어느 경로가 낮은지 확인 (낮은 게 이김)
LocPrf둘 다 100이면 MED가 결정자라는 증거 / 200이면 fix 적용됨
> 마커best path. 어느 Next Hop에 붙었는지 = 실제 선택된 경로
예시 출력 (문제 상황)
   Network                  Next Hop        Metric LocPrf Weight Path
*>i RD:A.A.A.0/24          <Site1-BL TEP>   59    100    0      i   ← best (낮은 MED)
* i RD:A.A.A.0/24          <Site2-BL TEP>   62     100    0      i   ← 탈락

# 진단: LocPrf 둘 다 100(tie) → MED 59 vs 62에서 결판 → 59(Site1) 승
# Site2 compute leaf에서도 동일 → Site2 트래픽이 Site1로 우회 = suboptimal
→
해결 확인

fix 적용 후 같은 명령 재실행 → local 경로의 LocPrf가 200으로 보이고 > best 마커가 자기 site BL Next Hop으로 이동하면 성공.

09 오해 정정 (Myth → Fact)

이 케이스에서 흔한 오해와, 실측·검증으로 확인된 사실을 대조한다.

✕ Myth (오해)
ACI는 OSPF cost를 MP-BGP MED로 반영하지 않는다 (MED=0 유지).
✓ Fact (실측)
이 환경에서는 OSPF cost가 MED로 상속된다. MED = core cost + BL local cost (48+11=59, 58+4=62).
✕ Myth
MED는 site간 경계에서 의미 없어지거나 리셋된다.
✓ Fact
MED는 EVPN으로 보존(transitive)되어 remote site leaf도 동일 값을 본다.
✕ Myth
Multi-Site는 기본적으로 각 site가 자기 local L3Out을 우선한다.
✓ Fact
그 기본 동작은 MED/LocPref 동률일 때만. MED가 다르면 깨지고 한쪽으로 쏠린다.
✕ Myth
OSPF cost를 맞추면 경로 문제를 해결할 수 있다.
✓ Fact
가능하나 취약·비결정적. 외부 변동에 다시 흔들림. Local Preference가 정답.
∑
검증 출처

ACI 전용 모델(ciscoDeepNetwork)이 실측과 일치하는 메커니즘을 설명했고, 공식 RAG(ciscodata)는 MED의 site간 보존과 "route-map으로 LocPref 조정"을 공식 문서로 확인. OSPF cost→MED 상속은 공식 문서에 명시는 없으나 실측으로 확정. (출처: §11)
