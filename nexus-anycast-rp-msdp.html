2대 Nexus 스위치 기준 · PIM Anycast-RP(RFC 4610) 방식과 MSDP 방식 비교

전제 토폴로지

항목N9K-1N9K-2
Loopback0 (Router ID / 소스)1.1.1.1/321.1.1.2/32
Loopback1 (Anycast RP 주소)5.1.1.1/325.1.1.1/32
RP 그룹 범위224.0.0.0/4224.0.0.0/4
핵심 개념
Loopback1(5.1.1.1/32)은 두 대에 동일한 IP를 부여하고 IGP로 광고한다. 소스/수신자는 라우팅상 가까운 RP에 붙는다. 두 RP 간 소스 정보를 동기화하는 수단이 PIM Anycast-RP 또는 MSDP로 나뉜다.

0. 공통 사전 설정

N9K-1

feature pim
feature ospf

interface loopback0
  ip address 1.1.1.1/32
  ip router ospf 1 area 0
  ip pim sparse-mode

interface loopback1
  ip address 5.1.1.1/32   ! Anycast RP
  ip router ospf 1 area 0
  ip pim sparse-mode

interface Ethernet1/1        ! 모든 L3 링크
  ip pim sparse-mode

N9K-2

feature pim
feature ospf

interface loopback0
  ip address 1.1.1.2/32
  ip router ospf 1 area 0
  ip pim sparse-mode

interface loopback1
  ip address 5.1.1.1/32   ! Anycast RP (동일)
  ip router ospf 1 area 0
  ip pim sparse-mode

interface Ethernet1/1        ! 모든 L3 링크
  ip pim sparse-mode
TIP — Loopback은 기본 /32로 광고된다. 두 RP의 코스트가 동일해 트래픽 분산 제어가 필요하면 ip ospf cost 로 우선순위를 조정한다.

0-1. IGMP Snooping 확인 필수

필수 확인 사항
L2 구간의 올바른 멀티캐스트 포워딩을 위해 해당 VLAN에서 IGMP Snooping이 반드시 활성화되어 있어야 한다. 비활성 상태이면 멀티캐스트 트래픽이 VLAN 내 모든 포트로 플러딩되거나, 반대로 수신자에게 전달되지 않는 문제가 발생한다.

상태 확인

! 전역 상태
show ip igmp snooping

! 특정 VLAN 상태 (예: VLAN 10)
show ip igmp snooping vlan 10

! 학습된 그룹 / 수신 포트
show ip igmp snooping groups vlan 10
show ip igmp snooping querier vlan 10
show ip igmp snooping mrouter vlan 10

정상이라면 출력에 아래 항목이 나타난다.

출력 항목정상 값설명
IGMP Snooping information for vlan 10표시됨해당 VLAN에 스누핑 인스턴스 존재
Snooping enabledEnabledVLAN 단위 활성 여부
IGMP querierIP 주소 표시Querier 부재 시 그룹 학습이 만료됨
Router ports1개 이상mrouter 포트 미검출 시 업링크 전달 실패

활성화 설정

! 전역 (NX-OS 기본값은 enable)
ip igmp snooping

! VLAN 단위
vlan configuration 10
  ip igmp snooping

! L3 SVI가 없는 L2-only VLAN이면 Querier를 반드시 지정
vlan configuration 10
  ip igmp snooping querier 10.10.10.254
체크 포인트
  • NX-OS는 IGMP Snooping이 기본 활성이지만, 운영 중 no ip igmp snooping 이 적용된 경우가 있으므로 반드시 실측 확인한다.
  • 해당 VLAN에 L3 SVI(PIM 동작)가 없으면 Querier가 존재하지 않는다. 이때는 ip igmp snooping querier 를 명시적으로 설정해야 한다.
  • vPC 환경에서는 양쪽 피어 스위치의 IGMP Snooping 설정이 동일해야 한다. 불일치 시 show vpc consistency-parameters vlan 에서 오류로 표시된다.
  • Querier가 없으면 스누핑 엔트리가 타임아웃되어 멀티캐스트가 간헐적으로 끊긴다.

1. 방식 A — PIM Anycast-RP (RFC 4610) 권장

NX-OS가 PIM Register 메시지를 피어 RP로 직접 relay 한다. 별도 프로토콜이나 TCP 피어링이 필요 없어 설정이 가장 단순하다.

N9K-1

ip pim rp-address 5.1.1.1 \
   group-list 224.0.0.0/4

ip pim anycast-rp 5.1.1.1 1.1.1.1
ip pim anycast-rp 5.1.1.1 1.1.1.2

N9K-2

ip pim rp-address 5.1.1.1 \
   group-list 224.0.0.0/4

ip pim anycast-rp 5.1.1.1 1.1.1.1
ip pim anycast-rp 5.1.1.1 1.1.1.2

문법

ip pim anycast-rp <anycast-RP-주소> <세트에 속한 개별 RP 주소>

  • 양쪽 스위치에 두 줄 모두 동일하게 입력한다 (자기 자신 포함).
  • 자기 자신 주소(로컬 Loopback0)는 relay 대상에서 자동 제외된다.

확인 명령

show ip pim rp
show ip pim group-range
show ip mroute
show ip pim internal event-history null-register

show ip pim rp 출력에 Anycast-RP 세트 멤버(1.1.1.1, 1.1.1.2)가 표시되면 정상.

2. 방식 B — MSDP 기반 Anycast RP

멀티벤더 혼재 환경이거나 도메인 간(inter-domain) SA 교환이 필요할 때 사용한다.

N9K-1

feature msdp

ip pim rp-address 5.1.1.1 \
   group-list 224.0.0.0/4

ip msdp originator-id loopback0   ! 1.1.1.1
ip msdp peer 1.1.1.2 \
   connect-source loopback0
  description MSDP-to-N9K-2

N9K-2

feature msdp

ip pim rp-address 5.1.1.1 \
   group-list 224.0.0.0/4

ip msdp originator-id loopback0   ! 1.1.1.2
ip msdp peer 1.1.1.1 \
   connect-source loopback0
  description MSDP-to-N9K-1
주의 — originator-id는 Anycast 주소(5.1.1.1)가 아니라 유니크한 Loopback0(1.1.1.1 / 1.1.1.2)를 지정해야 한다. Anycast 주소를 쓰면 SA 메시지가 RPF 체크에서 폐기된다. connect-source도 동일하게 Loopback0을 사용한다.

추가 옵션

! RP가 3대 이상일 때 SA flooding 억제 (N9K-1 기준)
ip msdp mesh-group ANYCAST-MESH 1.1.1.2

! MD5 인증
ip msdp password 1.1.1.2 <MD5키>

! SA 필터링
ip msdp sa-policy 1.1.1.2 SA-FILTER in
ip msdp sa-policy 1.1.1.2 SA-FILTER out

확인 명령

show ip msdp summary
show ip msdp peer 1.1.1.2
show ip msdp sa-cache
show ip msdp count
show ip pim rp

show ip msdp summary의 State가 Established여야 정상이다.

4. 공통 주의사항

  1. 두 방식을 동시에 적용하지 말 것. SA 중복 및 mroute 불일치를 유발한다.
  2. Anycast Loopback(5.1.1.1)에 ip pim sparse-mode가 누락되면 RP가 동작하지 않는다.
  3. Loopback0(1.1.1.1 / 1.1.1.2)와 Loopback1(5.1.1.1) 모두 IGP로 광고되어야 한다.
  4. VRF 환경이면 모든 명령을 해당 VRF 컨텍스트 하위에서 설정한다. 
    vrf context PROD
router ospf 1
  vrf PROD
! PIM / MSDP 명령은 config-vrf 하위에서
ip pim rp-address 5.1.1.1 group-list 224.0.0.0/4
  5. vPC 환경에서는 peer-link 멀티캐스트 동작 특성상 ip pim pre-build-spt 적용 및 RP용 / PIM 소스용 Loopback 분리를 검토한다.
  6. 장애 복구 시간은 IGP 수렴 시간에 종속된다. OSPF 타이머 튜닝 또는 BFD 적용을 권장한다.
