L3Out OSPF · 외부 경로 Cost / Metric 조정

L3Out을 OSPF로 구성했을 때, 외부에서 학습한 경로를 fabric 내부의 다른 Leaf로 전달하면서 선호도(metric)를 조정하는 정확한 방법. "Interface OSPF Cost가 아니라 Route Map(Route Profile)"이라는 핵심을 Cisco 공식 문서로 교차검증해 정리한다.

01 질문과 핵심 결론

1.1 원래 질문

Q

"ACI L3Out을 OSPF로 구성 시, 학습된 외부 네트워크를 내부 Leaf로 전달할 때 Cost를 조정하는 가장 좋은 방법은?"

1.2 한 줄 결론

★
Best Practice

외부에서 학습한 경로를 내부 Leaf로 전달할 때의 선호도 조정은 Border Leaf의 Interface OSPF Cost가 아니라 Route Map(Route Profile)의 Set Rule을 Import 방향에서 적용하는 것이 정답이다. 단일 metric(MED)보다 Set Local Preference(APIC의 Set Preference)를 우선 사용하면 fabric 내부 BGP best-path에서 더 결정적이고 예측 가능하게 동작한다.

1.3 왜 흔히 혼동하는가

"Cost 조정"이라고 하면 OSPF 인터페이스 cost를 먼저 떠올리기 쉽다. 그러나 ACI fabric 안에서 외부 경로가 다른 Leaf로 전파되는 매체는 OSPF가 아니라 MP-BGP다. 따라서 "내부 Leaf로 전달할 때"의 제어 지점은 OSPF가 아니라 BGP 속성이며, 이를 APIC에서 다루는 객체가 Route Map / Route Profile이다.

!
자주 하는 오해 — 정정

"OSPF cost가 redistribute될 때 BGP MED로 자동 상속된다"는 것은 사실이 아니다. ACI의 OSPF→MP-BGP interleak 과정에서 OSPF cost는 BGP MED로 자동 전달되지 않으며, 필요한 metric은 Route Profile의 Set Rule로 명시적으로 설정해야 한다. (상세: §5, 출처 [5])

02 외부 경로의 fabric 내부 전파 흐름

외부 OSPF neighbor에서 학습한 경로가 다른 Leaf까지 도달하는 전체 흐름이다. ★ 표시 지점이 바로 조정 포인트다.

External OSPF Neighbor
외부 라우터 / 방화벽 — OSPF로 external route 광고
↓OSPF (북쪽 / North)
★ Border Leaf (L3Out)
OSPF → MP-BGP VPNv4/v6 로 interleak (redistribute) — 여기서 Route Map 적용
↓iBGP VPNv4 (overlay-1 / infra VRF)
Spine (Route Reflector)
MP-BGP RR — 모든 Leaf로 reflect
↓iBGP VPNv4
Compute Leaf (수신 측)
VPNv4 경로를 user VRF로 import — best-path 선택 (Local Pref > Weight > … > MED)
i
핵심

모든 Leaf와 Spine은 동일 BGP AS 내에서 iBGP 세션을 맺고, 외부 경로는 overlay-1(infra) VRF 내에서 VPNv4/v6로 분배된다. 수신 Leaf는 이를 다시 사용자 VRF로 가져와 사용한다. 즉 "내부 Leaf로 전달" = MP-BGP 전파이며, 제어 대상은 BGP 속성이다.

출처: ACI Fabric L3Out White Paper [1], APIC L3 Networking Config Guide 6.2(x) — WAN/External Forwarding [2]

매핑

질문의 "내부 Leaf로 전달할 때 cost 조정" = Set Rule 을 Import 방향 Route Map에 넣는 것. North Interface OSPF Cost는 이 질문의 답이 아니다.

04 North(외부) vs South(내부) Metric 비교

두 가지 "cost"는 영향 범위와 설정 위치가 완전히 다르다. 이 구분이 이 주제의 핵심이다.

구분Interface OSPF Cost NorthRoute Control · Set Rule South
영향 범위L3Out ↔ 외부 OSPF neighbor 간 (북쪽 / outbound SPF)fabric 내부 MP-BGP 경로 전파 (남쪽 / 내부 방향)
프로토콜OSPFMP-BGP (VPNv4/v6)
설정 위치L3Out > Logical Interface Profile > OSPF Interface Policy (Cost of Interface)Route Map 의 Set Rule (Set Preference / Set Metric)
용도외부 OSPF SPF 계산에서 이 인터페이스 비용 조정내부 Leaf가 여러 Border Leaf 중 어디로 나갈지 제어
"내부 Leaf 전달"에 해당?✕ 아니오✓ 예 — 정확히 이 케이스
⚠
주의

Interface OSPF Cost를 올려도 내부 Leaf의 경로 선택은 바뀌지 않는다. 내부 선택은 BGP best-path가 결정하며, OSPF cost는 그 입력값으로 자동 상속되지도 않는다. 내부 선호도를 바꾸려면 반드시 Set Rule 을 써야 한다.

05 Set Local Preference vs Set Metric(MED)

5.1 왜 Local Preference가 우선인가

여러 Border Leaf가 같은 prefix를 광고할 때, compute Leaf는 BGP best-path 알고리즘으로 하나를 고른다. 그 우선순위에서 Local Preference는 MED보다 훨씬 위에 있다.

BGP best-path 우선순위 (높은 것부터)
Weight  (Cisco 독자, 로컬)
  > Local Preference   ← ★ Set Preference 로 제어 (권장)
  > Locally originated
  > AS-Path 길이
  > Origin
  > MED (Multi-Exit Discriminator)   ← Set Metric 으로 제어 (하위)
  > eBGP > iBGP
  > ...
★
결론

특정 Border Leaf 경로를 선호시키려면 Set Local Preference(Set Preference)를 권장한다. MED는 우선순위가 낮아 다른 속성에 의해 무력화될 수 있고, MED 비교에는 조건(같은 인접 AS 등)이 붙어 fabric 내부에서 덜 결정적이다.

5.2 ★ OSPF cost는 MED로 자동 상속되지 않는다

!
정정 — 공식 문서 기준

OSPF external route가 MP-BGP로 redistribute(interleak)될 때 OSPF cost가 BGP MED로 자동 상속되지 않는다. metric/preference/community는 Route Profile의 Set Rule을 통해 명시적으로 설정해야 적용된다.

출처: APIC L3 Networking Config Guide 6.2(x) — Route Control with Route Maps and Route Profiles [5]

속성APIC Set Rule 이름BGP 우선순위권장 용도
Local PreferenceSet Preference높음여러 Border Leaf 중 특정 경로 선호 (1순위 권장)
WeightSet Weight가장 높음로컬(해당 Leaf)에만 적용 — 범위 제한적
MED (Metric)Set Metric낮음외부에 광고하는 metric 또는 보조적 tie-break

06 설정 절차 (APIC GUI)

외부에서 학습한 prefix를 내부 Leaf로 전달할 때 Local Preference를 높여 특정 Border Leaf를 선호시키는 표준 절차다.

  1. Match Rule 생성 — 대상 prefix 매칭
    Tenant > Policies > Protocol > Match Rules for Route Map
    • 새 Match Rule 생성 후 Match Prefix 추가 (예: 특정 external subnet 또는 0.0.0.0/0)
  2. Set Rule 생성 — Local Preference 지정
    Tenant > Policies > Protocol > Set Rules for Route Map
    • 새 Set Rule 생성 후 Set Preference 체크 → 선호할 경로에 높은 값(예: 200) 부여
    • (선택) 보조적으로 Set Metric 추가 가능 — 단 MED는 하위 우선순위임을 인지
  3. Route Map(Route Profile) 생성 + Context 연결
    Tenant > Networking > L3Outs > [L3Out] > Route map for import and export route control
    • Route Map 생성, Type = Route Control
    • Context 추가 → Action = Permit, 위 Match Rule + Set Rule 연결
    • Direction = Import (외부→내부 수신 경로 조정)
  4. External EPG / Subnet 에 적용
    L3Out > External EPGs > [ExtEPG] > Subnet (또는 Route Control Profile)
    • 대상 subnet에 Import Route Control 범위 활성화 + 위 Route Map 연결
i
참고 — 관련 ACI 객체 (REST/MO)

위 GUI 설정은 내부적으로 다음 MO에 매핑된다: rtctrlProfile(Route Map), rtctrlCtxP(Context), rtctrlSubjP(Match), rtctrlAttrP(Set), rtctrlSetPref(Set Preference), rtctrlSetRtMetric(Set Metric).

✎
개념 예시 — 동등한 IOS 스타일 표현

이해를 돕기 위한 의사 표현(실제 ACI는 GUI/MO로 구성):

pseudo · route-map import (개념)
! 외부에서 받은 prefix를 내부로 전달 시 Local Pref 상향
ip prefix-list EXT_NETS permit 10.10.0.0/16
route-map IMPORT_PREF permit 10
  match ip address prefix-list EXT_NETS
  set local-preference 200   ! ← 이 Border Leaf 경로 선호

07 Default Route 선호 시나리오

실무에서 가장 흔한 케이스: 두 개의 L3Out(또는 두 Border Leaf)로 외부에서 0.0.0.0/0 default route를 받고, 하나를 Active, 다른 하나를 Standby로 쓰고 싶을 때.

방향조정 대상방법
외부로 광고(Export, 북쪽)0.0.0.0/0 광고 metricDefault Route Leak Policy + OSPF Interface 정책 / Export Set Metric
내부로 전달(Import, 남쪽)compute Leaf의 default 경로 선호도External EPG Route Control → Match 0.0.0.0/0 → Set Preference (Active 경로에 높은 Local Pref)
★
Active / Standby default

Active L3Out의 Import Route Map에서 0.0.0.0/0에 Set Preference = 200, Standby는 기본(100) 유지. compute Leaf는 Local Pref가 높은 Active 경로를 선택하고, Active 장애 시 자동으로 Standby로 수렴한다.

08 검증 결과표 (Cisco 공식 교차검증)

핵심 주장 5가지를 Cisco 내부 지식 소스(ciscodata)로 공식 문서와 대조한 결과다.

1
Border Leaf의 OSPF external route는 MP-BGP VPNv4로 redistribute되어 Spine(RR)을 거쳐 다른 Leaf로 전파된다
맞음
외부 경로는 BGP IPv4/IPv6 AF로 interleak되어 MP-BGP VPNv4/v6로 변환되고, overlay-1(infra) VRF 내에서 Spine RR을 통해 분배된다. 수신 Leaf는 user VRF로 재import한다.
출처: White Paper [1] · APIC L3 Config Guide 6.2(x) — WAN/External Forwarding [2]
2
"내부 Leaf 전달 시 metric 조정"은 Interface OSPF Cost가 아니라 Route Map Set Rule(Import)이다 / Interface OSPF Cost는 외부 SPF에만 영향
부분적 맞음
내용은 전부 정확하다. 내부 전파 metric은 Route Map으로 조정하고, Interface OSPF Cost는 외부 OSPF SPF에만 영향을 준다. ("부분적"은 표현 보강 차원이며 결론은 옳음.)
출처: White Paper [1] · Configure Route Control in ACI [4]
3
여러 Border Leaf 선호 시 Set Metric(MED)보다 Set Local Preference가 더 결정적/안정적이다
맞음
BGP best-path에서 Local Preference가 MED보다 우선순위가 높으므로 Set Preference 사용이 더 결정적이고 안정적이다. → Set Local Preference 권장.
출처: ACI Fabric L3Out White Paper — Route Profile/Route Map [1]
4
GUI 경로: L3Out > Route map for import/export route control, Match/Set Rule은 Policies > Protocol 하위
맞음
설정 경로 정확. Route Map은 Tenant > Networking > L3Outs > [L3Out] > Route map for import and export route control, Match/Set Rule은 Tenant > Policies > Protocol 하위.
출처: White Paper [1] · Configure Route Control in ACI [4]
5
OSPF cost가 MP-BGP redistribute 시 BGP MED로 자동 상속된다
정정 — 아니오
자동 상속되지 않는다. interleak redistribution 시 metric/preference/community는 Route Profile의 Set Rule로 명시적으로 설정해야 적용된다. (1차 답변의 "MED는 OSPF cost를 상속" 서술을 정정.)
출처: APIC L3 Networking Config Guide 6.2(x) — Route Control with Route Maps and Route Profiles [5]
∑
종합

1차 답변의 핵심 결론(Route Map Set Rule · Import 방향 · MED보다 Local Pref 우선)은 모두 공식 문서로 검증됨. 보조 설명 1건("OSPF cost→MED 자동 상속")만 틀렸고 정정 완료. 정정 내용은 오히려 "명시적 Set 필요"라는 핵심 권고를 더 강화한다.
